# 添加帧缓冲图形显示支持

## 技术说明

用户选择了"640x480 16色"，但标准 VGA 16色模式（Mode 12h）使用**平面内存模型**（4个位平面），编程极为复杂。  
本计划改用 **VBE 线性帧缓冲模式（640x480x8bpp，256色）**，内存布局为每像素1字节，连续线性排列，是 OS 开发的标准做法。  
"16色"在应用层体现为渲染时仅使用标准 VGA 16色调色板（索引 0~15），视觉风格与16色一致。

---

## Task 1：Multiboot 头添加视频模式请求

**文件**：`arch/x86/boot/boot.S`

- 在 `MB_FLAGS` 中加入 `MULTIBOOT_VIDEO_MODE`（`0x4`）：
  ```asm
  #define MB_FLAGS  (MULTIBOOT_MEMORY_INFO | MULTIBOOT_PAGE_ALIGN | MULTIBOOT_VIDEO_MODE)
  ```
- 在 `.multiboot` 节的三个 header 字段之后追加视频字段（Multiboot 1 规范）：
  ```asm
  .section .multiboot
      .long MULTIBOOT_MAGIC
      .long MB_FLAGS
      .long CHECKSUM(MB_FLAGS)
      /* video_mode_type: 0=linear graphics */
      .long 0
      /* width */
      .long 640
      /* height */
      .long 480
      /* depth (bpp) */
      .long 8
  ```
- 重新计算 `CHECKSUM`：新 flags = `0x07`，checksum = `-(0x1BADB002 + 0x07)` = `0xE4524FF7`

---

## Task 2：在 highmem fixmap 中预留帧缓冲映射区

**文件**：`includes/arch/x86/highmem.h`

- 在 `enum fixed_addresses` 中添加帧缓冲条目（80页 = 320KB，足够 640×480 = 307200 字节）：
  ```c
  FIX_FB_BEGIN,
  FIX_FB_END = FIX_FB_BEGIN + 79,
  ```
- 在 `includes/arch/x86/page.h` 或 `highmem.h` 中定义帧缓冲虚拟基址宏：
  ```c
  #define FB_VIRT_BASE  fix_to_virt(FIX_FB_END)  /* 帧缓冲虚拟起始地址 */
  ```

**注意**：`fix_to_virt(FIX_FB_END)` 是最低地址，`fix_to_virt(FIX_FB_BEGIN)` 是最高地址，共 80 页连续虚拟空间。

---

## Task 3：确保帧缓冲对应的 PDE 已分配

**问题**：`FIX_FB_BEGIN`~`FIX_FB_END` 对应的虚拟地址（大约在 `0xffea0000` ~ `0xffffa000` 附近）可能不在 boot.S 已分配的 128MB 初始页表范围内，其 PDE 可能为空，导致 `__set_fixmap()` 触发 "PAE BUG #00"。

**解决方案（在 `arch/x86/kernel/setup.c` 的 `setup_arch()` 中，在调用 `__set_fixmap` 之前）**：
- 在 `paging_init()` 完成后（此时 bootmem 分配器可用），为帧缓冲虚拟地址范围手动分配并填充 PDE 条目；
- 或在 `paging_init()` 内部扩展 fixmap PDE 初始化逻辑（当前 `highmem.c` 的 `fixed_kmap_init()` 只初始化了 `FIX_KMAP_BEGIN` 的 PTE 指针）。

具体实现：在 `highmem.c` 中新增 `fixmap_setup_fb()` 函数，为帧缓冲虚拟地址区间分配 PDE（若不存在）并创建对应的页表页。

## Task 4：新增帧缓冲驱动模块

**新文件**：
- `kernel/framebuffer.c`
- `includes/framebuffer.h`

**头文件 `includes/framebuffer.h` 接口设计**：

```c
#ifndef __FRAMEBUFFER_H__
#define __FRAMEBUFFER_H__
#include <stdint.h>

typedef struct {
    uint32_t phys_addr;     // 帧缓冲物理地址（来自 multiboot）
    uint32_t virt_addr;     // 帧缓冲虚拟地址（fixmap 映射后）
    uint32_t width;         // 像素宽
    uint32_t height;        // 像素高
    uint32_t pitch;         // 每行字节数（可能 >= width）
    uint8_t  bpp;           // 每像素位数（8）
} framebuffer_info_t;

extern framebuffer_info_t fb_info;

void fb_init(uint32_t phys_addr, uint32_t width, uint32_t height,
             uint32_t pitch, uint8_t bpp);
void fb_put_pixel(uint32_t x, uint32_t y, uint8_t color);
void fb_fill_rect(uint32_t x, uint32_t y, uint32_t w, uint32_t h, uint8_t color);
void fb_clear(uint8_t color);

/* 原始像素图像 blit：data 为 width*height 字节，每字节一个颜色索引 */
void fb_blit_image(uint32_t x, uint32_t y, uint32_t w, uint32_t h,
                   const uint8_t *data);

#endif
```

**`kernel/framebuffer.c` 实现要点**：
- `fb_init()`：保存参数，调用 `__set_fixmap()` 将物理帧缓冲页逐页映射到 `FIX_FB_BEGIN`~`FIX_FB_END`，最后设置 `fb_info.virt_addr`
- `fb_put_pixel()`：`*(uint8_t*)(fb_info.virt_addr + y * fb_info.pitch + x) = color`
- `fb_fill_rect()` / `fb_clear()`：基于 `fb_put_pixel` 的循环封装
- `fb_blit_image()`：逐行 memcpy 或逐像素写入

## Task 5：新增位图字体数据（8x16 VGA 字体）

**新文件**：`includes/font8x16.h`

- 包含 256 个字符的 8x16 像素位图数据（每字符 16 字节，共 4096 字节）
- 标准 VGA BIOS 字体数据，广泛公开可用
- 数据结构：
  ```c
  static const uint8_t font8x16[256][16] = {
      [0] = { 0x00, 0x00, ... },
      [65] = { /* 'A' */ 0x00, 0x00, 0x18, 0x3C, ... },
      ...
  };
  ```

## Task 6：适配 TTY 层支持帧缓冲输出

**文件**：`includes/tty/tty.h` 和 `kernel/tty/tty.c`

- 在 `tty.h` 中增加显示模式枚举和字体尺寸常量：
  ```c
  #define TTY_MODE_VGA_TEXT  0
  #define TTY_MODE_FB        1
  #define FONT_WIDTH  8
  #define FONT_HEIGHT 16
  void tty_set_mode(int mode);
  ```

- 在 `tty.c` 中：
  - 添加 `static int tty_mode = TTY_MODE_VGA_TEXT;`
  - `TTY_WIDTH` / `TTY_HEIGHT` 改为根据模式动态计算（帧缓冲模式：`640/8=80` 列，`480/16=30` 行）
  - `tty_put_char()` 中根据 `tty_mode` 分发：
    - 文本模式：保持现有 VGA 写入逻辑
    - 帧缓冲模式：调用 `fb_draw_char()` 绘制 8x16 字符位图
  - 新增 `fb_draw_char(x, y, c, fg, bg)` 函数：遍历 `font8x16[c]` 位图，按位设置像素颜色
  - `tty_clear()` 帧缓冲模式：调用 `fb_clear(bg_color)` 并重置光标
  - `tty_scroll_up()` 帧缓冲模式：可选实现真正的行滚动（memmove 帧缓冲数据），而非简单清屏

- 删除或保留 `tty_set_buffer_base()`（仅对文本模式有效，帧缓冲模式忽略）

## Task 7：在 setup_arch() 中初始化帧缓冲并切换 TTY 模式

**文件**：`arch/x86/kernel/setup.c`

在 `setup_arch()` 函数中，于 `paging_init()` 完成之后、其他 printk 调用之前插入：

```c
void __init setup_arch() {
    copy_multiboot_info();
    setup_memery();          // 含 paging_init()

    /* ---- 新增：帧缓冲初始化 ---- */
    if (multiboot_info_base->flags & MULTIBOOT_INFO_FRAMEBUFFER_INFO) {
        fb_init(
            (uint32_t)multiboot_info_base->framebuffer_addr,
            multiboot_info_base->framebuffer_width,
            multiboot_info_base->framebuffer_height,
            multiboot_info_base->framebuffer_pitch,
            multiboot_info_base->framebuffer_bpp
        );
        tty_set_mode(TTY_MODE_FB);
        tty_clear();  // 清屏（黑色）
    }
    /* ----------------------------- */

    acpi_tables_init();
    // tty_set_buffer_base(PAGE_OFFSET);  // 仅在文本模式下需要
}
```

## Task 8：图像显示 API 调用示例

在 `kernel/kernel.c` 的 `_kernel_main()` 中，帧缓冲初始化完成后，即可显示原始像素图像：

```c
// logo_data 为嵌入的原始像素数组（每字节 1 个颜色索引）
extern const uint8_t logo_data[];
extern const uint32_t logo_width, logo_height;

fb_blit_image(
    (fb_info.width  - logo_width)  / 2,   // 居中 X
    (fb_info.height - logo_height) / 2,   // 居中 Y
    logo_width, logo_height,
    logo_data
);
```

图像数据以 C 数组形式嵌入（`kernel/logo.c` 或单独 `.h` 文件），颜色索引对应 VBE 256色调色板中的标准 VGA 16色。
