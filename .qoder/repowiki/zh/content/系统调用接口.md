## 简介
本文件面向LulaOS的系统调用接口，系统性说明用户态到内核态的切换机制、参数传递与返回值处理、系统调用表的组织与分发、以及当前已实现的系统调用API。文档同时提供安全与权限方面的注意事项，并为用户态程序开发者给出API使用指南与示例思路。**最新更新**：sys_write()现已集成用户空间访问验证功能，显著提升了系统调用的安全性。

## 项目结构
围绕系统调用的关键代码分布如下：
- 入口与上下文切换：arch/x86/entry.S 中的 system_call 中断门（int 0x80）负责保存寄存器、切换到内核段、调用 do_syscall，并将返回值写回寄存器后返回用户态。
- 分发与实现：kernel/syscall.c 维护系统调用表，提供 do_syscall 分发器与若干内置系统调用实现（write、exit、getpid），并提供注册接口 register_syscall。
- 常量与类型：includes/interrupts/interrupts.h 定义系统调用号、NR_SYSCALLS、syscall_fn_t 等；includes/arch/x86/ptrace.h 定义 pt_regs 结构体，用于保存/恢复寄存器上下文。
- **新增**：用户空间访问验证：includes/arch/x86/uaccess.h 提供 access_ok()、copy_from_user()、copy_to_user() 等安全访问函数。

## 核心组件
- 系统调用入口（arch/x86/entry.S）：通过 int 0x80 触发，保存寄存器上下文，设置内核数据段，将 pt_regs 指针传给 do_syscall，并在返回前将结果写入 eax 槽位，最后 iret 回到用户态。
- 系统调用分发器（kernel/syscall.c）：从 regs->eax 读取调用号，校验范围与表项有效性，按表调用相应 sys_* 函数，并将返回值写回。
- 系统调用表与注册（kernel/syscall.c + includes/interrupts/interrupts.h）：静态数组 syscall_table[NR_SYSCALLS]，由 register_syscall 在初始化阶段填充；syscall_init 注册内置调用。
- 寄存器上下文（includes/arch/x86/ptrace.h）：pt_regs 描述进入系统调用时的寄存器布局，entry.S 压栈顺序与恢复顺序与之严格对应。
- **新增**：用户空间访问验证（includes/arch/x86/uaccess.h）：提供 access_ok()、copy_from_user()、copy_to_user() 等函数，确保内核安全访问用户态内存。

## 详细组件分析

### 用户态到内核态切换（int 0x80）
- 触发方式：用户态执行 int 0x80，CPU 自动加载内核CS/SS并跳转到 system_call。
- 上下文保存：entry.S 将 ebx..esi、ebp、es、ds、eax 等依次压栈形成 pt_regs，并设置内核数据段。
- 调用分发：将 pt_regs 指针作为参数传递给 do_syscall。
- 返回值处理：do_syscall 返回后，entry.S 将返回值写入 pt_regs->eax 槽位，然后按相反顺序弹出寄存器并 iret 返回用户态。

### 系统调用表与分发机制
- 表结构：静态数组 syscall_table[NR_SYSCALLS]，元素类型为 syscall_fn_t（五参 long 函数指针）。
- 初始化：syscall_init 将表清零，并注册 SYS_WRITE、SYS_EXIT、SYS_GETPID 对应的处理函数。
- 分发流程：do_syscall 从 regs->eax 取调用号，检查是否越界且表项非空，若合法则调用对应处理函数，否则返回 -1。
- 扩展性：新增系统调用只需定义 sys_xxx 并通过 register_syscall 注册到表中。

### 参数传递与返回值约定
- 参数传递：遵循 Linux ABI，调用号在 eax，参数依次在 ebx、ecx、edx、esi、edi。
- 返回值：统一以 long 形式返回，最终写入 regs->eax，用户态从 eax 获取。
- 寄存器上下文：entry.S 压栈顺序与 pt_regs 字段布局一致，确保 do_syscall 能正确访问各寄存器。

### 用户空间访问验证机制
**新增功能**：LulaOS 现在实现了完整的用户空间访问验证机制，确保内核安全地访问用户态内存。

- **access_ok()**：检查用户地址区间是否完全落在用户空间范围内（[0, TASK_SIZE)）
- **copy_from_user()**：从用户空间安全拷贝数据到内核缓冲区，包含地址验证和错误处理
- **copy_to_user()**：从内核空间安全拷贝数据到用户缓冲区
- **strncpy_from_user()**：安全地从用户空间拷贝字符串

**工作流程**：
1. 调用 copy_from_user() 进行数据拷贝
2. 内部调用 access_ok() 验证用户地址合法性
3. 如果验证失败，返回未拷贝字节数（全部失败）
4. 如果验证成功，使用 memcpy() 完成实际拷贝
5. 调用者根据返回值判断操作是否成功

### 已实现的系统调用API
当前内核实现了以下三个系统调用：

- **write**
  - 原型：long sys_write(long fd, long buf, long count, long d, long e)
  - **更新**：现在使用 copy_from_user() 进行安全的用户空间访问
  - 行为：通过用户空间访问验证函数将用户缓冲区数据拷贝到内核栈缓冲后再输出到控制台
  - 参数：fd（忽略）、buf（用户空间缓冲指针）、count（最大字节数）、d/e（忽略）
  - 返回：成功返回写入的字节数；失败返回 -EFAULT（用户地址非法）或 -EINVAL（参数非法）
  - 安全特性：包含用户地址验证、边界检查、缓冲区溢出防护
  - 参考路径：[kernel/syscall.c:31-56](file://kernel/syscall.c#L31-L56)

- **exit**
  - 原型：long sys_exit(long code, long b, long c, long d, long e)
  - 行为：打印退出码并停机（cli; hlt），当前无进程管理，直接 halt。
  - 参数：code（退出码），其余忽略
  - 返回：不可达（停机）
  - 参考路径：[kernel/syscall.c:62-69](file://kernel/syscall.c#L62-L69)

- **getpid**
  - 原型：long sys_getpid(long a, long b, long c, long d, long e)
  - 行为：占位实现，固定返回 PID=1（内核进程）
  - 参数：全部忽略
  - 返回：1
  - 参考路径：[kernel/syscall.c:75-79](file://kernel/syscall.c#L75-L79)

### 安全与权限考虑
**重大更新**：系统调用安全性得到显著提升

- **用户空间访问验证**：所有涉及用户态内存访问的系统调用现在都通过 uaccess.h 提供的函数进行安全访问
- **地址范围检查**：access_ok() 确保用户地址完全落在用户空间范围内，防止内核访问非法地址
- **缓冲区保护**：sys_write() 限制单次写入量（WRITE_BUF_MAX = 1024字节），防止内核栈溢出
- **错误处理**：用户空间访问失败时返回适当的错误码（-EFAULT），避免内核崩溃
- **内存清理**：当用户地址非法时，目标缓冲区会被清零，防止内核读取未初始化数据
- **未来增强**：计划引入异常表（exception table）支持需求分页和更精细的错误处理

## 性能考虑
- 系统调用开销主要来自上下文保存/恢复与表查找，当前为 O(1) 表索引，效率较高。
- **新增开销**：用户空间访问验证增加了额外的地址检查和可能的内存拷贝操作。
- 建议：
  - 减少不必要的 printk 调用（如 write 逐字符输出），可改为批量输出。
  - 在高频调用路径上避免额外分支与锁操作。
  - 未来可扩展为更高效的调用表（如分段表或哈希表）以降低冲突。
  - 考虑实现异常表机制以减少用户空间访问的性能开销。

## 故障排查指南
- 现象：调用未实现或调用号越界
  - 表现：返回 -1（-ENOSYS），内核打印"invalid syscall number"
  - 排查：确认调用号是否正确、是否在 NR_SYSCALLS 范围内、是否已通过 register_syscall 注册
  - 参考路径：[kernel/syscall.c:117-124](file://kernel/syscall.c#L117-L124)

- 现象：write 输出异常或崩溃
  - **更新**：现在会返回 -EFAULT 而不是直接崩溃
  - 可能原因：用户态 buf 指针无效或 count 过大
  - 建议：检查用户态缓冲区地址的有效性和可读性
  - 参考路径：[kernel/syscall.c:45-49](file://kernel/syscall.c#L45-L49)

- 现象：用户空间访问失败
  - 新现象：系统调用返回 -EFAULT 错误码
  - 可能原因：用户地址超出用户空间范围、地址对齐问题、权限不足
  - 调试：检查 access_ok() 的验证逻辑和用户态内存布局
  - 参考路径：[includes/arch/x86/uaccess.h:65-77](file://includes/arch/x86/uaccess.h#L65-L77)

- 现象：exit 导致系统停机
  - 说明：当前实现直接 cli; hlt，属于预期行为
  - 建议：在具备进程管理后，实现进程退出逻辑而非停机
  - 参考路径：[kernel/syscall.c:62-69](file://kernel/syscall.c#L62-L69)

## 结论
LulaOS 的系统调用接口基于 int 0x80 实现，采用统一的寄存器 ABI 与 pt_regs 上下文，通过静态表分发到具体 sys_* 处理函数。**重要更新**：系统调用现在集成了完整的用户空间访问验证机制，显著提升了安全性和健壮性。当前已实现 write、exit、getpid，具备可扩展的注册机制。后续应继续完善权限控制机制，并考虑引入异常表以支持需求分页和更高效的错误处理。

### 用户空间访问API
**新增功能**：用户态程序开发者需要了解新的用户空间访问机制

- **access_ok(addr, size)**：检查用户地址区间是否合法
  - 参数：addr（用户空间起始地址）、size（访问字节数）
  - 返回：1 = 合法，0 = 非法

- **copy_from_user(to, from, n)**：从用户空间拷贝数据到内核
  - 参数：to（内核目标缓冲区）、from（用户源地址）、n（拷贝字节数）
  - 返回：未拷贝字节数（0 = 成功，n = 失败）
